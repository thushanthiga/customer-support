# Apptimate One ERP — Authoritative Database Catalog & Schema Reference

> **Immutable Schema Architecture Specification**  
> This catalog is the permanent, authoritative architectural reference for tenant databases in the Apptimate One ERP platform. The physical database structure, table definitions, column types, primary/foreign keys, and cross-table relationships are invariant across all tenants. All analytical queries generated by the support assistant must adhere strictly to the tables, columns, constraints, and canonical recipes documented herein.

---

## 1. System-Wide Architectural & Query Principles

### 1.1 Read-Only Security Boundary
The analytics assistant operates with **strict read-only permissions** (`SELECT` statements only). Mutation statements (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`) are strictly forbidden and intercepted by database security guardrails.

### 1.2 Tenant & Organization Scoping
- Each tenant database is strictly isolated (`apptimate_<tenant>`).
- Every operational table contains `organization_id` referencing `core_organizations.id`.
- The SQL compiler (`organization_conditions`) automatically injects tenant organization scoping at execution time. The query planner does not need to manually inject `organization_id` filters or join on `organization_id`.

### 1.3 Soft Deletion Standard (`deleted_at`)
Most operational tables implement soft deletion via a timestamp column `deleted_at`.
When querying active operational records, always filter: `<table>.deleted_at IS NULL`.
Tables supporting soft-delete include: `inventory_items`, `sales_orders`, `sales_goods_issue_notes`, `finance_invoices`, `procurement_purchase_orders`, `core_parties`, `core_warehouses`, etc.

### 1.4 Single-Column Join DSL Standard
- The JSON query plan DSL uses single-column equality joins: `left_table.left_column = table.right_column`.
- Multi-column joins or conditional join ON clauses are neither needed nor permitted by the compiler.
- In 1-to-1 relationships (e.g. `inventory_items.id = inventory_item_replenishment_rules.item_id`), filter variant/warehouse qualifiers in WHERE/filters (`variant_id IS NULL`, `warehouse_id IS NULL`), never in join ON clauses.

### 1.5 Common Table Expressions (CTEs) & Window Functions
- CTEs are authored inside the `ctes` array property of the plan.
- The outer query joins CTEs by their declared `name` as if they were base tables.
- Window functions (`ROW_NUMBER()`, `RANK()`, `SUM() OVER (...)`) are computed inside CTEs and filtered in the outer query.

### 1.6 Critical Column Naming Standards
- `core_parties`: Party name is **`first_name`** (and optionally `last_name`). `core_parties` has **NO `name` column**.
- `finance_invoices`: Invoices have `type = 'ar'` (customer sales invoices) and `type = 'ap'` (supplier purchase bills). Gross amount is **`amount_due`** (NO `grand_total` column). Amount paid is **`amount_settled`**. Outstanding balance is `amount_due - amount_settled`.
- `inventory_stock_balances`: Physical stock on hand is `qty_on_hand`; unreserved available stock is **`qty_available`** (NO `stock` or `quantity` column).
- `sales_orders` & `procurement_purchase_orders`: Order total amount is **`grand_total`**.
